# 衡语内核架构（Heng Core v2）

> 本文档定义「衡语作为独立编程语言」的执行内核。
> 与旧实现（`heng/` 目录）的根本区别：旧实现的求值靠 Python 的 dict / list / 递归函数栈，
> 本质是「中文语法 + Python 求值器」；新内核自己拥有指令集、调用栈、值表示与堆，
> Python 只承担「把源码编译成字节码」这一件事。

## 一、为什么必须换内核

旧实现的性能天花板由 Python 决定，这是结构性问题，不是调参能解决的：

| 负载 | 旧实现（Python 求值） | 新内核实测目标 |
|---|---|---|
| 递归 fib(28) | 约 20 秒量级（fib(25) 已 1.9 秒） | 亚秒级 |
| 每步开销 | Python 函数调用 + dict 查找 + isinstance 分派 | 数组索引 + 整数运算 |

更关键的是语义自主性。旧实现的「量纲安全」「沙箱授权」都是在外层加检查打补丁；
新内核把这些做成**指令级**保证（见第五节），因此它们不可能被绕过。

## 二、分层架构

```
  源码 .hng (UTF-8 纯文本)
        │
        ▼
  ┌──────────┐   中文最大匹配 + 别名归一化
  │  词法层   │   → Token 流
  └──────────┘
        │
        ▼
  ┌──────────┐   递归下降，产出 AST
  │  语法层   │
  └──────────┘
        │
        ▼
  ┌──────────┐   量纲代数 / 类型标注 / 错误签名 / 能力检查
  │  检查层   │   → 带类型标注的 AST（IR 的输入）
  └──────────┘
        │
        ▼
  ┌──────────┐   变量槽位分配 / 常量池 / 跳转回填
  │  代码生成 │   → .hbc 字节码（独立二进制格式）
  └──────────┘
        │
        ▼
  ┌──────────┐   自研栈式 VM：自有指令指针、调用栈、值栈、堆
  │  虚拟机   │   → 与 Python 运行时无关
  └──────────┘
```

**关键分界**：`.hbc` 是完整、自足的字节码产物。它不包含任何 Python 对象引用，
可以脱离 Python 源码独立加载运行（未来可移植到 C 写的 VM 上执行）。

## 三、值表示

VM 的值栈上只放统一编码的 64 位单元，避免解释期的动态类型分派：

```
值槽 val = (tag: u8, payload: u64)

tag 常量：
  0  NIL        空
  1  NUM        数，payload = float64 位模式
  2  BOOL       真假，payload = 0 / 1
  3  TEXT       文本，payload = 堆对象索引
  4  SEQ        序列，payload = 堆对象索引
  5  MAP        映射，payload = 堆对象索引
  6  RECORD     记录，payload = 堆对象索引 + 布局 id
  7  CAP        能力
```

数值统一为 f64（与量纲系统一致；量纲在编译期已消除，运行期只算数）。
文本/序列/映射存于 VM 自有堆（见第六节），不借用 Python 容器。

## 四、指令集（草案 v0.1）

栈式、定长操作码 + 变长立即数。按功能分为九组：

### 4.1 常量与栈
```
NOP                       空操作
PUSH_NUM  <f64>           压入数值常量
PUSH_BOOL <u8>            压入布尔
PUSH_NIL                  压入空
PUSH_STR  <常量池索引>     压入文本常量
POP                       丢弃栈顶
DUP                       复制栈顶
SWAP                      交换栈顶两项
```

### 4.2 变量（槽位寻址，编译期已确定下标）
```
LOAD_LOCAL  <u16>         读局部槽位
STORE_LOCAL <u16>         写局部槽位
LOAD_GLOBAL <u16>         读全局槽位
STORE_GLOBAL <u16>        写全局槽位
```

旧实现的变量查找是「沿 Env 链逐层 dict 查找」，递归时每帧多次哈希；
新内核用**编译期解析出的槽位下标**，退化为一维数组索引。

### 4.3 算术与比较（数值）
```
ADD SUB MUL DIV           数 四则（DIV 检查除零 → 错误<除零>）
NEG                       取负
EQ NE LT LE GT GE         比较，结果压入真假
NOT                       逻辑非
```

### 4.4 控制流
```
JMP     <i32 相对偏移>     无条件跳转
JMP_IF  <i32>             栈顶为真则跳
JMP_IFNOT <i32>           栈顶为假则跳
```

`如果 / 循环 / 重复 N 次 / 每个` 全部编译为跳转，不使用宿主递归。

### 4.5 函数调用（自有调用栈）
```
CALL   <u16 函数索引> <u8 实参数>
RET                       返回
RET_NIL                   无值返回
```

调用约定：实参从**右到左**压栈，被调函数用 `LOAD_LOCAL 0..n-1` 读取参数，
局部变量紧接参数之后编号。帧由 VM 的调用栈管理，与 Python 栈无关。

### 4.6 文本与集合
```
CONCAT                    文本拼接
LEN                       取长度（文本字符数 / 序列元素数）
INDEX_GET                 取下标（序列/映射）
INDEX_SET                 写下标
MAKE_SEQ   <u16 元素数>    从栈上弹出 n 个元素构造序列
MAKE_MAP   <u16 键值对数>  从栈上构造映射
MAKE_REC   <u16 记录id> <u8 字段数>
FIELD_GET  <常量池索引>    读记录/映射字段
```

### 4.7 输出与错误
```
PRINT                     弹出栈顶并输出（含单位格式化）
THROW    <错误类别索引>     抛出衡语错误
```

### 4.8 能力与沙箱（指令级安全）
```
CAP_CHECK <能力名索引>     当前帧必须具备能力，否则 错误<未授权>
```

这是新内核相对旧实现的**结构性优势**：能力检查写在指令流里，
不存在「某个代码路径忘了检查」的漏洞（旧实现正是因此出过一次真实绕过）。

### 4.9 终止
```
HALT                      正常结束
```

## 五、量纲：编译期消除，运行期零成本

量纲代数是衡语最有价值的独有设计，但旧实现在运行期重复做单位向量运算。
新内核的做法：

1. 检查层为每个数值表达式算出维度向量（长度/时间/质量/金额/计数/温度）；
2. 不匹配直接编译期报错，不生成字节码；
3. 生成代码时**丢弃单位**，只保留 f64 运算；
4. 单位信息仅用于输出的格式化（常量池里记录显示用单位字符串）。

结果是：量纲安全是**零运行时开销**的静态保证，而不是运行期检查。
这一点旧实现做不到，因为它把单位挂在运行期值上。

## 六、内存模型

VM 自有堆，对象统一带头部：

```
堆对象 = (kind: u8, refcount: u32, size: u32, payload...)
  kind: TEXT / SEQ / MAP / RECORD / CLOSURE

TEXT   payload = UTF-8 字节串
SEQ    payload = val[]（元素为统一值槽）
MAP    payload = (键文本, val)[]（小规模线性查找；超过阈值转哈希索引）
RECORD payload = 字段 id → val
```

回收策略（分阶段）：
- v0.1：**引用计数**，指令级插入 INCREF/DECREF（文本拼接、容器赋值处）；
- v0.2：加**循环检测**（试删除算法，类似 CPython 的 gc）；
- 长线：可换成分代回收，但接口保持不变。

为什么不用 Python 的 GC：因为要能脱离 Python 运行；且 Python 的对象模型
（每个值一个 PyObject）会让 value-stack VM 失去性能优势。

## 七、与旧实现的语义对照

新内核**必须**保持相同的可观察语义（否则教材与示例失效），逐项对照：

| 语义点 | 旧实现 | 新内核 |
|---|---|---|
| 关键字 / 别名归一化 | 词法层 | 相同（直接复用规则定义） |
| 量纲代数 | 运行期值携带单位 | 编译期消除，输出时格式化 |
| 错误签名 `可能生` | 类型层校验 | 检查层校验，`THROW` 指令带类别 |
| 沙箱能力 | 运行期 set 检查（曾出漏洞） | `CAP_CHECK` 指令，不可绕过 |
| 并发 `同时/发起/接收` | Python 线程 | 见第八节 |
| 结构化 IR 展示 | 字符串 trace | `.hbc` 反汇编（真实指令流） |

## 八、并发模型

旧实现用 Python 线程，受 GIL 限制，且归属不清晰。新内核采用**协作式调度**：

- VM 持有任务表，每个任务有自己的值栈与帧栈；
- `发起` 把函数调用登记为新任务（不进线程）；
- `接收` 在当前任务无消息时**让出**，调度器切换到其他任务；
- `同时` 块结束时会合所有子任务。

这是「单线程内的真并发」——没有数据竞争，没有 GIL，行为确定可复现。
（对 AI 编排场景，这比抢占式线程更合适：工具调用是 IO 等待型而非 CPU 密集型。）

## 九、目录结构

```
heng2/                    新内核，与 heng/ 完全独立
  __init__.py
  token.py                词法单元
  lexer2.py               词法分析（中文最大匹配）
  ast2.py                 AST 节点
  parser2.py              递归下降

  check2.py               检查层
  bytecode.py             指令集定义 + 编码/解码
  compiler2.py            AST → 字节码

  __main__.py             python3 -m heng2
```

## 十、验收标准

新内核必须满足以下可测条件，否则不算「新语言」：

1. **无 Python 求值参与**：VM 执行字节码时，除输入输出外不调用任何
   用户级 Python 函数；`vm.py` 中不存在 `eval` / `exec` / 递归解释 AST。
2. **字节码自足**：`.hbc` 可先写入磁盘、再由独立进程加载执行，结果一致。
3. **性能数量级提升**：fib(28) 相对旧实现提速至少 10 倍。
4. **语义等价**：现有示例程序的输出与旧实现逐字节一致。
5. **量纲零开销**：带单位与不带单位的同构程序，指令数一致。
6. **能力不可绕过**：`CAP_CHECK` 由指令保证，构造性攻击测试无法越过。
