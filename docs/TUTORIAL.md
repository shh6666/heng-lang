# 衡语入门与实践（内核 v2）

> **环境准备**：安装后直接在终端用 `henger`；
> 未安装时可用 `python3 -m heng2` 从仓库源码运行。
>
> ```sh
> henger 你好.hng          # 编译并运行
> henger --check 你好.hng  # 只检查
> henger --debug 你好.hng  # 单步调试
> ```

> 本教材配套衡语内核 v2。所有示例都在原生 C 虚拟机上实际跑通过，
> 执行命令统一为 `henger 示例.hng`（也可用 `python3 -m heng2` 从源码运行）。

## 第一章 第一次运行

### 1.1 你好，衡语

新建 `hello.hng`：

```hl
开始:
  说出 "你好，衡语"
结束
```

运行：

```bash
henger hello.hng
```

输出 `你好，衡语`。

三个必须记住的规则（第 4 条补充在 1.3 节）：

1. 程序主体写在 `开始:` 与 `结束` 之间；
2. 缩进不参与语法，但**保持两个空格**便于阅读；
3. `结束` 负责闭合一个块，有几层块就有几个 `结束`。

### 1.3 两个易踩的写法

**`否则 如果` 不能连写**，要嵌套：

```hl
如果 条件甲:
  说出 "甲"
否则:
  如果 条件乙:
    说出 "乙"
  结束
结束
```

**序列与映射字面量必须写在一行内**。想表达长序列就先换行再拼接，
或用多行变量逐步追加。

### 1.2 程序是怎么跑起来的

衡语不是解释中文关键字的转译层。真实路径是：

```
源码 → 词法 → 语法 → 检查 → 代码生成 → 字节码(.hbc) → 原生虚拟机执行
```

Python 只负责前半段「源码变字节码」。执行发生在独立的 C 程序里，
它只认字节码，不认 Python。这也是为什么：

```bash
henger --build hello.hng    # 产出 hello.hbc
henger --run hello.hbc      # 不读源码，直接跑字节码
```


### 2.2 量纲：衡语最有价值的设计

给数加上单位，编译器就会替你检查单位是否用得对。

```hl
开始:
  变量 单价 : 数 元/个 = 10
  变量 数量 : 数 个 = 3
  变量 总价 : 数 元 = 单价 * 数量
  说出 总价
结束
```

输出 `30元`。注意 `元/个 × 个 = 元`，单位是**自动约掉**的。

如果写错了呢：

```hl
开始:
  变量 消耗 : 数 元 = 100
  变量 线索 : 数 个 = 20
  变量 结果 : 数 元 = 消耗 * 线索
  说出 结果
结束
```

编译期直接报错：`量纲不匹配`。因为 `元 × 个` 不等于 `元`。

这类错误在业务代码里极难发现——单位错了，数字看着是对的，结论却全错。
衡语让它在编译期就暴露。

## 第四章 函数

### 4.1 定义与调用

```hl
定义 做法 单线成本(消耗 : 数 元, 线索 : 数 个) -> 数 元/个:
  返回 消耗 / 线索
结束

开始:
  说出 单线成本(80000<元>, 2000<个>)
结束
```

输出 `40元/个`。签名里写清了参数与返回值的**类型和单位**，
调用时传入 `80000 元` 和 `2000 个`，返回 `40 元/个`。

### 4.2 递归

```hl
定义 做法 阶乘(n : 数) -> 数:
  如果 n <= 1:
    返回 1
  结束
  返回 n * 阶乘(n - 1)
结束

开始:
  说出 阶乘(5)
结束
```

### 4.3 契约：写在签名里的约定

```hl
定义 做法 安全除(甲 : 数, 乙 : 数) -> 数:
  约定:
    要求: 乙 != 0
    保证: 结果 > 0
  结束
  返回 甲 / 乙
结束

开始:
  说出 安全除(10, 2)
结束
```

`要求` 在进入函数时检查，`保证` 在返回前检查。违反就报错。

## 第五章 错误处理

### 5.1 抛出与捕获

```hl
定义 做法 检查(值 : 数) -> 数 可能生 错误<越界>:
  如果 值 < 0:
    报错 错误<越界>("值不能为负")
  结束
  返回 值
结束

开始:
  尝试:
    说出 检查(-1)
  接住 错误<越界> 为 原因:
    说出 "接住了：" + 原因
  最后:
    说出 "无论如何都会执行"
  结束
结束
```

`可能生 错误<越界>` 是**错误签名**：这个函数可能抛出「越界」类错误。
调用方必须用 `尝试` 包裹，否则编译期会提示。

### 5.2 内置错误类别

| 类别 | 触发场景 |
|---|---|
| `错误<除零>` | 除数为 0 |
| `错误<越界>` | 下标越界 |
| `错误<类型>` | 类型不匹配 |
| `错误<断言>` | 契约不成立 |
| `错误<未授权>` | 沙箱内未授权 |

## 第八章 权限与沙箱

### 8.1 能力声明

有能力副作用的操作（网络、文件、工具调用）必须在沙箱里显式授权。

```hl
开始:
  沙箱:
    授权 工具.查询
    执行 回执 = 工具.查询("招生日报")
    观察 回执:
      如果 回执.状态 = "完成":
        说出 回执.内容
      结束
    结束
  结束
结束
```

`授权` 是编译期声明的白名单，由虚拟机在指令级强制。
**没有「某处忘了检查」的可能**——这是把权限做成指令的好处。

### 8.2 执行与观察

`执行 X = 某调用` 执行一个能力调用；`观察 X:` 打开它的返回值检查
（相当于对返回结构做一次契约检查）。

## 第九章 并发

### 9.1 同时做事

```hl
定义 做法 查渠道(名称 : 文本, 毫秒 : 数) -> 文本:
  执行 回执 = 工具.慢查询(名称, 毫秒)
  返回 回执.结果
结束

开始:
  同时:
    发起 查渠道("抖音", 300)
    发起 查渠道("快手", 300)
    发起 查渠道("视频号", 300)
  结束

  接收(查渠道_信箱) 为 甲
  接收(查渠道_信箱) 为 乙
  接收(查渠道_信箱) 为 丙

  说出 甲
  说出 乙
  说出 丙
结束
```

三个查询各耗 300 毫秒，但总耗时约 300 毫秒——**它们真的在同时跑**。
每个任务在独立线程上执行。

### 9.2 等待完成

只要一个结果时，用 `等待完成` 更简洁：

```hl
定义 做法 求成本(消耗 : 数 元, 线索 : 数 个) -> 数 元/个:
  返回 消耗 / 线索
结束

开始:
  变量 成本 : 数 元/个 = 等待完成 求成本(80000<元>, 2000<个>)
  说出 成本
结束
```

### 9.3 并发安全规则

这条规则必须记住：**任务内不能修改外层变量**。

```hl
开始:
  变量 总 : 数 = 0
  同时:
    发起 某任务()
    总 = 总 + 1        ← 编译期报错
  结束
结束
```

原因很实在：两个任务同时写 `总`，结果不可预测。衡语不让这种代码通过编译。

正确做法是让任务**返回**结果，在父任务里串行汇总：

```hl
开始:
  变量 总 : 数 = 0
  同时:
    发起 计算(1)
    发起 计算(2)
  结束
  接收(计算_信箱) 为 甲
  接收(计算_信箱) 为 乙
  总 = 甲 + 乙
  说出 总
结束
```

## 第十章 FFI：直接调用 C 库

衡语可以直接调用 C 动态库，不需要任何中间层。

```hl
导入 外部 "libm" 之 数学

开始:
  说出 数学.sqrt(16)
  说出 数学.pow(2, 10)
结束
```

`导入 外部 "libm" 之 数学` 声明加载 `libm`，别名 `数学`。
之后 `数学.sqrt(...)` 就是真正的 C 函数调用。

沙箱内这样做需要授权：

```hl
导入 外部 "libm" 之 数学

开始:
  沙箱:
    授权 外部.调用数学
    说出 数学.sqrt(16)
  结束
结束
```

### 10.1 支持的签名

| 参数类型 | 返回值 | 例子 |
|---|---|---|
| 若干个数 | 数 | `数学.pow(2, 10)` |
| 一个文本 | 文本 | `C.strdup("x")` |
| 两个文本 | 文本 | `C.strstr("abc", "b")` |

### 10.2 平台差异

库名会自动适配：macOS 上 `libm` 映射到 `libSystem.dylib`，
Linux 上映射到 `libm.so.6`。写 `libm` 即可，不必关心平台。

## 第十一章 综合实战：渠道投放分析

把前面学到的组合起来。

```hl
定义 记录 渠道投放:
  字段 名称 : 文本
  字段 消耗 : 数 元
  字段 展现 : 数 次
  字段 线索 : 数 个
结束

定义 做法 单线成本(投放 : 渠道投放) -> 数 元/个 可能生 错误<除零>:
  如果 投放.线索 = 0<个>:
    报错 错误<除零>("线索为零，无法计算成本")
  结束
  返回 投放.消耗 / 投放.线索
结束

定义 做法 评级(成本 : 数 元/个) -> 文本:
  如果 成本 <= 40<元/个>:
    返回 "优"
  结束
  如果 成本 <= 60<元/个>:
    返回 "良"
  结束
  返回 "待优化"
结束

开始:
  变量 数据 : 序列 渠道投放 = [渠道投放("抖音信息流", 80000<元>, 2000000<次>, 2000<个>), 渠道投放("快手短剧", 50000<元>, 1600000<次>, 1600<个>), 渠道投放("搜索品专", 10000<元>, 0<次>, 0<个>)]

  每个 数据 为 投放:
    尝试:
      变量 成本 : 数 元/个 = 单线成本(投放)
      说出 投放.名称 + "｜" + 化成文(成本) + "｜" + 评级(成本)
    接住 错误<除零> 为 原因:
      说出 投放.名称 + "｜数据异常：" + 原因
    结束
  结束
结束
```

运行结果：

```
抖音信息流｜40元/个｜优
快手短剧｜31.25元/个｜优
搜索品专｜数据异常：线索为零，无法计算成本
```

这个程序用到了：记录、量纲、错误签名、try/catch、遍历、文本拼接。
**单位错了会在编译期报错，线索为零会在运行期被接住**——两层防护都在。

# 第四部分 工具链与工程化

## 第 27 章 模块化：把程序拆成多个文件

单文件写到几千行就该拆了。衡语用 `导入` 引入同目录的 `.hng`：

```hl
注：统计.hng（与主文件放在同一目录）
常量 累计 : 映射 文本 数 = {}

定义 做法 记(键 : 文本, 值 : 数) -> 空:
  如果 字典.有键(累计, 键):
    将 累计[键] + 值 放到 累计[键]
  否则:
    将 值 放到 累计[键]
  结束
结束

定义 做法 取(键 : 文本) -> 数:
  返回 累计[键]
结束
```

主文件：

```hl
注：main.hng
导入 「统计.hng」之 统计

开始:
  统计.记("抖音", 97000)
  统计.记("抖音", 3000)
  说出 统计.取("抖音")
结束
```

输出 `100000`。

**三条规则**：

1. `导入 「文件名.hng」之 别名`，之后用 `别名.函数名` 调用
2. 模块内部可以有自己的 `常量`（用来存状态），**每个模块的状态互相独立**
3. 模块里的函数可以互相调用，导入方看不到内部细节

> **两个常见错误**：
> 1. `导入 统计.hng 之 统计`（少了书名号「」）→ 报「导入失败：找不到模块」。
>    中文文件名必须用「」包起来。
> 2. 模块放在子目录（如 `lib/统计.hng`）时，`导入 「统计.hng」` 找不到——
>    导入只搜索「主文件所在目录」。目前请把模块放在与主文件同一目录。

## 第 28 章 单步调试

程序结果不对，又不确定哪一行出错时，用 `--debug`：

```sh
henger --debug 你的程序.hng
```

输出形如：

```
── 程序输出 ──
30

── 单步轨迹（每步的 PC 与变量）──
停 ▶ pc=0|slots=3
  [0] tag=0
  [1] tag=0
  [2] tag=0
停 ▶ pc=12|slots=3
  [0] 数 = 10
  [1] tag=0
  [2] tag=0
停 ▶ pc=21|slots=3
  [0] 数 = 10
  [1] 数 = 20
  [2] tag=0
```

`pc` 是指令序号，`[n]` 是变量槽位。看到 `数 = 10` 就知道那一刻变量已经是 10 了。

**在断点处停**（只停指定指令）：

```sh
henger --debug 你的程序.hng 12,25
```

在 pc=12 和 pc=25 处停，输出那一刻的全部变量。

## 第 31 章 写大型程序的注意事项

写了十来个真实项目（含一个 1200 行的手机 OS 原型）之后，总结出来的坑：

**1. 标识符不能以关键字开头**

```hl
定义 做法 结束进程(...)   ← 报「期望 做法名（遇到 KW_END 结束）」
定义 做法 销毁进程(...)   ← 对
```

`结束`、`执行`、`接收`、`模块`、`输出`、`时间`、`空` 都是关键字。
取名时避开这些字打头。

**2. 顶层不能声明变量**

```hl
变量 全局 : 数 = 0        ← 报错：期望顶层定义

常量 全局 : 映射 文本 数 = {}   ← 对，用映射承载可变状态
```

**3. 表达式跨行只能在括号内**

```hl
变量 总 : 数 = (甲 + 乙
  + 丙)                  ← 对的，在括号内换行

变量 总 : 数 = 甲 + 乙
  + 丙                   ← 错的，第二行被当作新语句
```

**4. 链式调用后不能再接字段或下标**

```hl
进化.最优基因().适应度      ← 语法错误
文字.分行(t)[0]            ← 语法错误

变量 g : 任意 = 进化.最优基因()    ← 拆成两步
变量 行 : 序列 文本 = 文字.分行(t)
说出 行[0]
```

**5. `文字.截` 和 `文字.从` 语义不同**

```hl
文字.截("按钮|RUN", 3)   → "按钮|"   取前 3 个
文字.从("按钮|RUN", 3)   → "RUN"     从第 3 个开始
```

解析带前缀的字符串（事件、路径、日志行）**一律用 `文字.从`**。
用错会导致「条件永远不成立」，而且编译器不会报错——这是最难查的一类 bug。

**6. `字典.删键` 是原地修改**

```hl
字典.删键(缓存, 键)          ← 正确
缓存 = 字典.删键(缓存, 键)   ← 也行，返回的还是同一个映射
```
