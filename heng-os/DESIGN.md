# 衡 OS：AI 自进化手机操作系统原型

> 用衡语写一个「操作系统级」的项目，压测语言与 VM 的极限。
> 目标不是真能开机，而是把手机 OS 的核心子系统用同一门语言实到位，
> 并且在其中做出「AI 自进化」这个真实可验证的机制。

## 一、为什么选这个题目

前 300 个验证项目 + 3 个工具，暴露缺陷的规律很清楚：
**算法题 0 个，业务题 6 个，真实工具 4 个**。形态越接近真实系统，越能撞出问题。

手机 OS 是「形态最复杂」的那一类：
- 多模块（内核、调度、内存、驱动、应用运行时、UI、AI）
- 长生命周期状态（进程表、内存映射、进化谱系）
- 严格的不变量（内存不能越界、调度不能饿死、权限不能提权）
- 需要持久化（镜像、配置、进化历史）

## 二、子系统划分

```
┌──────────────────────────────────────────────┐
│  应用层  App 运行时 / 权限沙箱 / 生命周期      │
├──────────────────────────────────────────────┤
│  AI 层   自进化引擎：策略基因、变异、选择、固化 │
├──────────────────────────────────────────────┤
│  服务层  通知 / 存储 / 电源 / 网络抽象         │
├──────────────────────────────────────────────┤
│  内核层  进程表 / 调度器 / 内存管理 / 系统调用  │
├──────────────────────────────────────────────┤
│  硬件抽象  帧缓冲 / 输入 / 时钟 / 传感器        │
└──────────────────────────────────────────────┘
```

## 三、AI 自进化机制（核心创新点）

不是「调用大模型」，而是**可验证的进化算法**：

1. **基因**：调度策略由一组参数编码（时间片、优先级权重、老化速率）
2. **评估**：给每个基因打分 = 吞吐 + 公平性 − 能耗
3. **选择**：保留前 N，淘汰后 N
4. **变异**：对保留者做参数扰动（含交叉）
5. **固化**：最优基因写入「镜像」，下次启动直接加载

关键：**进化过程可复现**（固定伪随机种子），结果可对比。

## 四、镜像（ISO）

真 ISO 是光盘镜像格式，这里做「**衡 OS 镜像**」：
- 固定头部（魔数、版本、子系统表）
- 分区表（内核/应用/AI 基因/配置）
- 校验和（保证镜像完整）
- 可被 `挂载` 读取，也可被 `重新打包`

## 五、验收标准

| 项 | 标准 |
|---|---|
| 内核 | 进程创建/销毁/调度不变量成立（无饿死、无重复回收） |
| 内存 | 分配/释放配对，越界被拒 |
| 应用 | 权限越界被拒，崩溃不影响其他应用 |
| AI | 进化 100 代，适应度单调不降（允许小波动） |
| 镜像 | 打包→校验→挂载→内容一致 |
| 启动 | 从镜像启动到「桌面就绪」，输出完整引导日志 |
