# 衡 OS —— AI 自进化手机操作系统原型

**全部用衡语编写。** 内核、调度、内存、权限、AI 进化、镜像、图形控制台，无一例外。

## 运行

```sh
henger src/boot.hng          # 命令行完整启动流程
henger src/selftest.hng      # 不变量自检（16 项）
henger src/dashboard.hng     # 图形控制台
```

## AI 自进化机制

不是调用大模型，而是**可复现的进化算法**：

- **基因**：调度策略三个参数（时间片、老化速率、优先级权重）
- **适应度**：`吞吐 × 10 + 公平性 × 500 − 切换次数 × 2`
  - 吞吐 = 完成数 / 时钟
  - 公平性 = 1000 / (1000 + 等待时间方差)
- **进化**：保留前 50% → 交叉 → 每代变异 3 个
- **可复现**：线性同余伪随机，固定种子 20261122

实测 20 代：适应度 804.45 → **851.93**（+47.48），时间片收敛到 7.36。

## 开发中发现并修复的缺陷

这个项目压出了 5 个语言级缺陷：

**1. 跨模块函数调用完全不可用（严重）**

```hl
导入 「m.hng」之 模
模.翻倍(21)      // 报「未定义的函数 模.翻倍」
```

根因：`模.翻倍` 被解析成 `Field(obj=模, name=翻倍)`，而检查器与编译器都只认 `VarRef("模.翻倍")`。模块导入了、函数也改名了，但一调用就炸——**模块系统形同虚设**。

修：检查器与编译器都支持 Field 形式的模块调用。

**2. 跨模块常量不可访问**

`内核.内核["内存总量"]` 报「未定义变量 内核」。根因：模块常量没被加命名空间前缀，且检查器不认「带点名字」的常量。

修：导入时给常量加前缀 + 改写模块内引用（含 `SetVar.target` 与记录构造）+ 检查器/编译器支持带点常量。

**3. 记录类型名带前缀后不匹配**

`内核.内存块` 与 `内存块` 被判定为不同类型。修：`same_type` 按短名归一。

**4. 链式调用后接字段/下标不支持**

```hl
进化.最优基因().适应度     // 语法错误
文字.分行(t)[0]           // 语法错误
```

修：改为两步赋值（语言层暂不支持，已记入 Skill 文档）。

**5. 镜像校验可被绕过（安全漏洞）**

在镜像末尾追加一个字符，校验和的数字部分不变（`化为数("51168X")` 静默截成 `51168`），于是**篡改照样通过校验**。

修：校验和必须是纯数字 + 末行必须是 CHECKSUM + 不许出现多个 CHECKSUM。

**6. 权限提升漏洞（安全漏洞）**

「恶意应用」在清单里写 `root` 就真拿到了 root。根因是只查「应用自己声明的权限列表」，等于应用自己说有什么就有。

修：加系统保留权限白名单（root / 内核.写 / 系统.关机），注册时剔除、申请时拒绝。

## 这个项目证明了什么

前 300 个算法验证项目**一个缺陷都没撞出来**。这个 OS 项目撞出 6 个，其中 2 个是安全漏洞。

原因很清楚：
- 算法题：短函数、纯计算、单文件
- OS 项目：7 个模块、跨模块调用与状态、长生命周期、严格不变量

**验证项目的形态比数量重要。** 一个真实系统顶一百道算法题。
